# Security Policy

Security reports are welcome and should be handled privately whenever possible.

## Reporting a vulnerability

Please **do not open a public issue containing vulnerability details, credentials, secrets, exploit steps, or other sensitive information**.

Use the repository's **Report a vulnerability** / private vulnerability reporting feature when it is available.

If private vulnerability reporting is not enabled, use the contact links on the [QvarcY GitHub profile](https://github.com/QvarcY) to request a private communication channel. Do not include sensitive technical details in a public message.

When reporting a vulnerability, please include enough information to reproduce and understand the issue, such as:

- affected repository and version or commit
- impact
- reproduction steps or proof of concept
- relevant environment details
- any suggested mitigation, if known

## Supported versions

Unless a repository states otherwise, security fixes are generally considered for the latest maintained version or the current default branch.

There is no guaranteed response or remediation SLA, but actionable reports will be reviewed as time allows.

Repository-specific security policies override this default policy.
