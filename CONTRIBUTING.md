# Contributing

Thanks for taking the time to contribute.

These are the default contribution guidelines for repositories maintained under the **QvarcY** account. A repository may provide its own instructions; when it does, those take precedence.

## Before you start

- Read the repository README and any project-specific documentation.
- Search existing issues and pull requests before opening a new one.
- Keep changes focused. Avoid unrelated refactors or formatting churn.
- For larger changes, consider opening an issue first so the approach can be discussed.

## Reporting a bug

A useful bug report includes:

- a clear description of the problem
- steps to reproduce it
- expected and actual behavior
- relevant environment or version details
- logs, screenshots, or a minimal reproduction when useful

Please do not report security vulnerabilities in a public issue. See [SECURITY.md](SECURITY.md).

## Proposing a feature

Describe the problem you want to solve, the expected benefit, and any alternatives you considered. A concrete use case is more useful than a feature request without context.

## Pull requests

A good pull request should:

- solve one clear problem
- explain what changed and why
- link the related issue when applicable
- include tests or validation where practical
- update documentation when behavior or usage changes
- avoid unrelated changes

Please make sure you understand and can explain the code you submit, including code created with automated or AI-assisted tools.

## Review

Not every proposal will be accepted. Decisions may depend on project scope, maintenance cost, backwards compatibility, complexity, and whether the change fits the direction of the repository.

Thanks for helping make the project better.
